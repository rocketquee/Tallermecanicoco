Apex Elite Motorsport · Documentación técnica

Arquitectura del sistema

Apex Elite Motorsport opera con una arquitectura de tres capas: un panel React en el navegador, una API REST en FastAPI y una base de datos PostgreSQL. Cada salto entre piezas viaja por un protocolo distinto y queda autenticado con JWT.

3 capas Frontend React + TypeScript Backend FastAPI + SQLAlchemy Datos PostgreSQL 16 · 21 tablas Seguridad JWT HS256 por rol

Capa cliente

Usuario

Administrador, recepción y mecánicos entran desde el navegador del taller: computadora de recepción, tablet o celular del dueño.

  • Administrador
  • Recepción
  • Mecánico

Sesión: correo y contraseña; el servidor devuelve un token con el rol y los permisos.

HTTPS navegador ↔ Vite

Capa de presentación

Frontend

Panel en React que dibuja el tablero de bahías, los expedientes de clientes y las órdenes. No calcula dinero ni decide permisos: solo presenta lo que autoriza la API.

  • React 19
  • TypeScript
  • Vite
  • Tailwind
  • Axios

Peticiones: adjunta Authorization: Bearer en cada llamada a /api/v1.

REST / JSON /api/v1 · UTF-8

Capa de aplicación

Backend

API REST que valida cada petición, aplica las reglas del taller (etapas, privacidad, inventario) y escribe en una sola transacción la orden, el detalle y la bitácora.

  • FastAPI
  • Pydantic v2
  • SQLAlchemy
  • JWT HS256
  • Uvicorn

Privacidad: el rol Mecánico nunca recibe precios y los clientes confidenciales salen enmascarados.

SQL psycopg2 · PostgreSQL

Capa de persistencia

Base de Datos

PostgreSQL guarda las 21 tablas del negocio con borrado lógico: nada se elimina físicamente. La bitácora y el historial de etapas son inmutables y están protegidos por triggers.

  • PostgreSQL 16
  • psycopg2
  • UTF-8
  • FK RESTRICT

Auditoría: cada cambio de etapa o de inventario deja rastro con usuario, fecha y hora.

Flujo de una petición

Del clic del mecánico a la fila en PostgreSQL

01

Inicio de sesión

El navegador envía POST /api/v1/login por HTTPS con correo y contraseña.

02

Token con rol

FastAPI verifica el hash scrypt y devuelve un JWT firmado con el rol del usuario.

03

Petición autenticada

El frontend adjunta el token en cada llamada REST y recibe JSON listo para pintar.

04

Transacción SQL

El backend abre una transacción: valida stock, escribe el detalle, descuenta inventario y audita.

05

Respuesta filtrada

La API enmascara precios y datos confidenciales según el rol antes de responder.

Reglas de comunicación

Contratos que sostienen la arquitectura

HTTPS / TLS

Todo el tráfico del navegador viaja cifrado. En desarrollo Vite hace proxy a la API local.

REST / JSON

Recursos versionados en /api/v1. Errores con detail legible y códigos HTTP estándar.

SQL parametrizado

SQLAlchemy arma las consultas con parámetros: nunca se concatena texto del usuario.

Transacciones atómicas

Si falla un paso de la operación, no se guarda nada; inventario, etapa y bitácora quedan consistentes.
